## 已确认的源码事实

- 当前 H3 通过 `AiHubMixMediaProvider` 异步提交和轮询。
- H3 请求支持 4–15 秒、2K、首尾帧和图片/视频参考。
- 当前 H3 供应商请求不发送 `negative_prompt`，不得增加未经验证的请求字段。
- 当前规划器会产生 `prompt_enhancements` 和 `negative_prompt_suggestions`。
- 剧本 `breakpoint` 已能把片段文本、关联角色和场景带入视频工作室。
- 角色库已有参考图、声音描述和动作片段；场景库已有参考素材。
- 当前质量档为 `preview`、`standard`、`cinematic`。
- 当前 `quality_check` 只读取宽高、时长和供应商元数据，不能判断实际画面。
- 当前生产容器没有 GPU 模型运行环境，独立模型必须通过硬件无关服务协议接入。

## 目标

在现有规划节点与 `provider_generate` 之间增加确定性的 H3 提示词编译能力，提高人物脸部稳定性、多人空间关系和肢体行为连续性。模型选择和模型参数不是本任务重点。

## 必须实现

1. 定义结构化 `ShotSpec`，至少包含：
   - 时长、景别、机位和单一运镜；
   - 每个角色的稳定标识、名称、外观不变量、初始位置和朝向；
   - 按时间顺序排列的动作阶段；
   - 多人互动顺序、接触点和结束姿态；
   - 对白说话人、情绪、声音提示和音效；
   - 场景、光线、上一镜头连续性和下一镜头落点；
   - 脸部、手部、足部和全身完整性要求；
   - 拆镜建议及其原因。
2. 新增代码白名单工作流节点 `h3_prompt_compile`，通过节点注册表暴露，不允许管理员上传或执行任意代码。
3. 在默认视频工作流中把节点放在规划/视频资产规划之后、路由和生成之前；旧工作流版本继续可回放。
4. 编译输入必须来自当前工作流状态、角色卡、场景卡、剧本片段和用户原始提示，不能由前端自行拼接成为权威事实。
5. 把负面建议转换为明确的“必须保持”“不得出现”正向约束，不把 `negative_prompt` 发送给 H3。
6. 多人提示词按稳定角色顺序输出；相同结构化输入必须得到逐字一致的编译结果。
7. 默认动作规则：
   - 支持最多 4 个已关联角色；
   - 4–8 秒为推荐镜头长度，仍遵守 H3 的 4–15 秒接口范围；
   - 每个角色在一个镜头中只有一个主要动作；
   - 明确起势、主体动作、接触时刻和落势；
   - 超过 2 人的高速交互、严重遮挡或多人同时手部接触只输出拆镜建议，不擅自改变剧情。
8. 对话镜头优先生成中近景、可见说话者面部和稳定机位的约束；全景不得承诺无法获得的五官细节。
9. H3 参考素材继续使用已验证的 `type + url` 请求结构，不添加供应商已拒绝的 `role` 字段；角色含义通过稳定顺序和提示词描述表达。
10. 任务事件保存编译后的提示词审计快照和 `ShotSpec` 摘要，但必须过滤签名 URL、对象存储凭据、API key 和内部文件路径。
