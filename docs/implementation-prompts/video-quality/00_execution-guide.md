# ZaoLang 视频质量优化提示词执行指南

## 用途

本目录中的 Markdown 文件是交给其他 LLM 执行源码修改的独立任务提示词。本目录本身不代表任何功能已经实现，也不得作为真实模型质量验证证据。

## 执行顺序

| 顺序 | 提示词 | 重要性 | 依赖 |
|---|---|---:|---|
| 1 | `P0-01_h3-prompt-compiler.md` | 必须 | 无 |
| 2 | `P0-02_candidate-domain-and-pricing.md` | 必须 | 无 |
| 3 | `P0-03_media-processor-protocol.md` | 必须 | 无 |
| 4 | `P0-04_content-aware-video-quality.md` | 必须 | P0-02、P0-03 |
| 5 | `P0-05_candidate-review-flow.md` | 必须 | P0-02、P0-04 |
| 6 | `P0-06_end-to-end-regression.md` | 必须 | P0-01 至 P0-05 |
| 7 | `P1-01_targeted-video-repair.md` | 重要 | P0 全部 |
| 8 | `P1-02_optional-face-temporal-enhancement.md` | 可选 | P0 全部 |
| 9 | `P2-01_wan-animate-sandbox.md` | 实验 | P0 全部 |

P0-01、P0-02、P0-03 可以分别交给不同 LLM 并行处理；其余任务按顺序执行。并行任务合并后，后续 LLM 必须重新检查当前工作树，不能依据旧代码快照继续修改。

## 统一执行规则

- 目标仓库固定为 `/Users/mac001/project/zaolangai/zaolang`。
- 每次执行前阅读仓库 README、适用的 `AGENTS.md`、相关领域技能说明和现有测试。
- 先检查 `git status --short`，保留所有无关的已有修改。
- 只实施当前提示词定义的任务，不顺手重构相邻模块。
- 不下载模型权重，不调用收费模型，不执行 GPU 推理。
- 所有测试使用 fake provider、固定媒体夹具和模拟质量报告。
- PostgreSQL 继续作为任务、候选、审核、积分、发布和制品的唯一事实源。
- 浏览器不得直连模型供应商、裸 ComfyUI 或媒体处理服务。
- 不向产品用户暴露 GPU 型号、文件路径、权重名称或 ComfyUI JSON。
- 保持上传、报价、积分预扣/结算、鉴权、幂等、异步轮询、取消和发布兼容。
- 不得把 fake provider、静态检查、接口占位或计划描述成真实模型效果验证。

## 每个执行任务的最终交付格式

执行 LLM 必须在最终答复中分别列出：

1. 已修改的行为和公共接口；
2. 数据迁移及兼容策略；
3. 实际运行的测试及结果；
4. 未运行或无法验证的项目；
5. 新增模型、许可证和数据流向；
6. 仍然存在的风险；
7. 关键源码文件的绝对路径链接。

## 完成定义

只有 P0-01 至 P0-06 全部完成、相互兼容并通过回归后，才可以称为“视频质量 P0 闭环已实现”。P1、P2 任一提示词单独完成，都不能替代内容级质检、候选追踪和人工审核。
