# Consumer Frontend

## Scope

The current consumer routes under `front/src/app/[locale]/(site)/` and the component families they share. **Trust the actual `page.tsx` files, shared components, and visual e2e specs**, not a fixed page count from a doc — dark theme is the acceptance baseline.

## Invariants

1. **The access token lives only in memory.** Storing it in `localStorage` turns any XSS into permanent account takeover; the durable half is the httpOnly refresh cookie. On reload, every component that depends on auth state must tolerate the intermediate "no token yet, silently refreshing" moment.
2. **Refresh requests are coalesced**: `client.ts`'s `refreshInFlight` guarantees concurrent 401s trigger only one refresh. Don't implement your own retry inside a component.
3. **Protected actions go through the login wall + action recovery**: intercept → open `login-dialog` → on success, resume via `pendingAction`; on cancel, the action is **discarded**, never silently executed.
4. **Any endpoint that moves credits requires an `idempotencyKey`** (submitting a generation, purchasing credits).
5. **Every interactive component implements the full state set**: `default / hover / focus-visible / disabled / loading / error` (+ `selected`). Missing `focus-visible` gets caught by the accessibility suite.
6. **No UI component library** — that's how theme-token drift starts. Components consume semantic tokens only (see `zaolang-theming`); **never a hardcoded colour**.
7. **No horizontal overflow at any of the three breakpoints**: 1440×1024 / 1024 / 390×844, asserted as `scrollWidth === clientWidth`. The visual QA suite checks this page by page.
8. **All copy goes through next-intl** — hardcoded Chinese strings are never allowed (see `zaolang-i18n-region`).
9. **The command palette is a combobox, not a dialog**: `role="search"` container + `role="combobox"` input + `role="listbox"`/`role="option"`. This ARIA structure is checked by axe — read `e2e/a11y.spec.ts` before touching the markup.
10. **Video creation parameters must stay provider-safe**: `VideoGenerationStudio`'s user controls only ever submit 4–15 seconds (`DURATIONS`), nine framings split by orientation — `LANDSCAPE_ASPECTS` `16:9`/`4:3`/`21:9`/`3:2`, `PORTRAIT_ASPECTS` `9:16`/`3:4`/`2:3`/`9:21`, plus `adaptive` as a third orientation of its own; there is deliberately **no `1:1`**, so orientation is always a meaningful first choice — one of four client resolution tiers `480p`/`720p`/`1080p`/`2K` (default `1080p`), an optional seed, and mutually exclusive normal-reference/first-last-frame modes. The studio's tiers are vendor-neutral: `back/app/providers/base.py` maps each onto the vendor's own token (`720p` is a synonym set that includes MiniMax H3's `768P`), so `768P` survives on the frontend only in `admin/models/llm-providers-panel.tsx`'s per-vendor pricing dimension, never as a studio option. Duration and aspect still hard-filter a candidate that cannot honour them. **Resolution is a user ceiling, not a must-match** — all four tiers stay offered and `request_json.resolution` is never rewritten on submit; after the final model is chosen, `adapt_resolution_tier` maps downward (never 1080p→2K) and only fails if that candidate has no mappable studio tier. When a model is forced, `generation-resolution.ts` previews the same adapted tier from `GET /v1/generation-jobs/models` `resolutions`. **A video remix path omits `video_options.resolution`** (`sourceIsVideo ? {} : { resolution }`) so the provider default applies and `wan2.7-videoedit` is not given a fabricated tier; aspect/duration mismatches still drop the candidate. Uploads only ever pass a platform `Asset.id` — never a webhook, external URL, or arbitrary provider JSON inside `extra`. A video remix also puts the licensed source `current_version.output_asset_id` into `reference_asset_ids`.
11. **`/studio-editor/{cutId}` (the cut editor, under the chrome-less `(studio)` route group; the legacy `/create/short/{cutId}` only `redirect()`s there) is a hard desktop Chrome/Edge gate** — `features/editor/gate.tsx`'s `EditorGate`, wrapped around `DramaEditor` and `gold-sample.tsx`: below the `md` width or outside Chrome/Edge it renders an `EmptyState` notice only, never the timeline — don't reuse the studio's mobile bottom sheet here. This route is excluded from `a11y-mobile` scanning. A job page's "enter editing" link imports only `front/src/features/editor/from-job.ts` — never the `features/editor` barrel (that pulls WASM/mediabunny into the job page). `export-runner.ts` dynamically imports `mediabunny`. Details: `zaolang-editor-drama`.
12. **RSC list pages degrade gracefully when the API is unavailable — never a blank screen.** `serverFetchOrNull` / `adminFetchOrNull` collapse network failures and 5xxs into `null` (`ApiError.isUnavailable`). Discover, profile work lists, and admin statistics already follow this. The route-level fallback is `front/src/app/[locale]/error.tsx`.
13. **A `POST`-initiated SSE stream is a different shape from `use-job-stream.ts`'s GET feed, not a variant of it.** Shared reader: `lib/sse-post.ts` (`thinking` / `delta` / `complete` / `error`). Callers: script turns, prompt polish, edit-plan, admin debug-chat. The whole reply arrives on the body of the single request that started it, so there is no `Last-Event-ID`/reconnect/poll-fallback. Errors from a failed request must be parsed into an `ApiError` from the response body (mirroring `apiRequest`'s envelope handling) — throwing the raw response text shows the user a JSON blob instead of the backend's `error.message`. **Job GET streams treat `event_type === "thinking"` as live reasoning, not a stage:** do not write it into `STAGE_FOR_EVENT`, do not store it in `events`, do not touch `lastEventId` / `sequence` (an undefined sequence is `NaN` in `Math.max`). Show it with `components/ai/thinking-disclosure.tsx` (`aria-live="polite"`) under the current stage. Refresh does not replay in-flight thinking.
14. **`/studio-editor/{cutId}` (gated by the `web_editor_enabled` runtime flag → `Me.features.web_editor`, plus `EditorGate`; its legacy alias `/create/short/{cutId}` just redirects), `/create/script` plus `/create/script/{episodeId}/clip` (`script_studio_enabled` → `features.script_studio`), and `/create/tools/canvas` plus `/canvas/{canvasId}` (`canvas_studio_enabled` → `features.canvas_studio`) are feature-flag-gated, so none of them is in the visual/a11y suites' page lists** — those lists (`e2e/visual.spec.ts`'s `PAGES`, `e2e/a11y.spec.ts`'s `PUBLIC_PAGES`) are deliberately public/anonymous-reachable pages only. Don't add a gated route there; it would either need seeded auth state or fail the sweep. `/create/short` itself (the drama-series dashboard: list series, drill into episodes, content-links, canonical work) is sign-in-gated only, not feature-flag-gated — see `zaolang-editor-drama` invariant #17 — and is already in both lists.
15. **The notification center has exactly one live source of truth**: `NotificationCenterProvider` is the only component that opens `use-notification-stream.ts`'s SSE connection (`GET /v1/notifications/stream`, backend-shared with the job stream's Redis pubsub — see `zaolang-generation-jobs`); the bell, the toast stack, and the full `/notifications` page all read from `useNotificationCenter()` / their own `GET /v1/notifications` fetch, never open a second stream. A right-side creation toast is keyed by `target_id` (not the notification `id`), because a job/export/script/draft-publish upserts one row across its whole lifecycle — keying by `id` would already dedupe correctly by construction, but keying by `target_id` explicitly is what makes "replace the card in place and push its timer back out" trivial to reason about (`notification-center-provider.tsx`'s `toasts` map). This toast is a separate surface from `components/ui/toast.tsx`'s bottom-center `ToastProvider`, and deliberately not deduped against it — an in-editor `export-panel.tsx` success/error toast and the same event's top-right creation toast can both be showing at once; that redundancy is intentional (the top-right one is the only one visible from anywhere else in the app) rather than a bug to fix by suppressing one. `CREATION_TARGET_TYPES` must stay aligned with the backend upsert targets (`generation_job` / `editor_export` / `episode_script` / `draft`).

16. **"Image Creation" is one card/operation with an asset-kind dimension layered on top, not three cards.** `ImageGenerationStudio` derives `image_to_image` from `text_to_image` the moment a reference image is attached (same pattern `VideoGenerationStudio` uses for `text_to_video → image_to_video`); the asset-kind picker is a second, independent axis on top of that (`general` / `character` / `scene` / `cover`), sets `assetKind`/`targetCharacterId`/`targetSceneId`/`autoAttachAsset` on the submit payload (see `zaolang-generation-jobs`), and is otherwise inert — don't reintroduce separate `text_to_image`/`image_to_image`/"edit" cards to express an asset-kind distinction that already lives in this picker. **`character` is a single option, not three** — a character's front/side/back turnaround views used to be three separate asset kinds (`character_front`/`_side`/`_back`); they are now one `ImageAssetKind.CHARACTER` plus an independent `CharacterViewAngle`. The studio only ever submits the default (`['front']`), which the planner treats as **one multi-panel character sheet** (left full-body three-view, right close-ups + palette — see `zaolang-generation-jobs` / `zaolang-agent-gateway`). Web no longer offers "补全侧面/背面": the library card shows that one sheet, and `InlineImageResult` has no completion button. Side/back completion remains an API/iOS path (`character_views: ['side']`/`['back']`, `_CHARACTER_COMPLETION_FIXED_PROMPTS` + anti-collage negative); `CHARACTER_COMPLETION_PROMPT` / `findCompletionJobFor` stay so an older draft can still merge those outputs into the gallery. Don't add a per-view picker back into the studio form. **`ImageGenerationStudio` never fetches or renders style preset / system style ("画风库")** — that picker (`useStyleAndSkillPicker`) is used by `VideoGenerationStudio` and `AudioGenerationStudio`. Don't add the gallery/preset half to the image shell to "keep parity" with video/audio; the removal was deliberate. **`VideoGenerationStudio` does not render the creation-skill Select** (`showCreationSkillSelect: false`); image and video both apply skills via `@` in `PromptField` (`useAppliedSkills`): only free or already-purchased skills whose `applicable_operations` include the current operation (empty means any *for templates*); selecting one strips the in-progress `@query`, merges `prompt_suffix`/`aspect_ratio`, and submits `skill_ids`. An image-asset recipe (`character`/`scene_asset`/`cover_asset`) is mentionable only when it *declares* a non-empty operation list that includes the current op — a user-authored roster skill with empty ops stays out of `@` and keeps going through the dedicated character/scene library. Applying an image-asset recipe also hangs its cover / first `reference_assets` still on the image studio's reference rail (removable). Audio is the remaining studio that still offers unlock-from-Select. Platform short-drama catalogue rows stay video-only; the image `@` list is the `image-*` style templates plus the dual-form `asset-*` image-asset recipes. Plaza detail CTAs use `creationStudioHref`: image-only skills (and every image-asset recipe) go to `/create/new?mode=image_creation&skillId=&assetKind=`, video-only templates to `video_creation` (a `character` recipe that resolves to video also carries `videoAssetKind=character_action`) — do not POST `/apply` on the plaza or usage double-counts. **Three jump-outs share this picker** — the character library (`characterImageStudioHref` / `characterSheetPrompt` in `lib/characters.ts`, `returnTo=/create/characters`), the scene library (`sceneImageStudioHref` / `sceneImagePrompt` in `lib/scenes.ts`, `returnTo=/create/scenes`), and the script studio's "生成角色设定图/场景图", which goes through its own wrappers in `features/script/script-prompts.ts` (`characterImagePrompt` wraps `characterSheetPrompt` but first runs `characterAppearanceWithMedium`, injecting `DEFAULT_CHARACTER_MEDIUM` when the traits name no visual medium; `sceneImagePrompt` there is a *different* function from `lib/scenes.ts`'s same-named export — it composes from `ScriptScene.blocks`, not name+description). `returnTo=/create/script/{episodeId}`. `ImageGenerationStudio`'s `initialAssetKind`/`initialTargetCharacterId`/`initialTargetSceneId`/`subjectNameHint`/`returnTo`/`returnLinkKind`/`returnLinkLabel` props (populated by `/create/new/page.tsx` from validated query params — `sanitizeReturnTo` allows the exact paths `/create/characters` and `/create/scenes` and any `/create/script/` prefix, never the raw string) exist only to pre-fill this same asset-kind/target state, not a second code path. A fresh character or scene jump-out with an existing main image and empty `uploads` seeds that sheet/hero into the reference rail (removable). On a terminal job, `InlineImageResult` shows a return button (`returnToCharacters` / `returnToScenes` / `returnToScript`) back to `returnTo`, carrying `linkKind`/`linkLabel`/`linkRefId` (from `GenerationJobResponse.linked_character_id`/`linked_scene_id`, see `zaolang-generation-jobs` invariant #15) only for a succeeded job that actually linked something — a failed/cancelled job still gets the button, just without a `linkRefId` to auto-relink. This `returnTo`/`returnLinkKind`/`returnLinkLabel`/`linkRefId`/`subjectNameHint` naming is this project's first "jump out, do one thing, jump back with the result" deep-link convention — reuse these same names rather than inventing a parallel set.
17. **The generic "我的技能" tab (`collection` page's `skills` tab, `manage-skill-dialog.tsx`) never sees an `IMAGE_ASSET_SKILL_CATEGORIES` skill.** `skill_library_service.list_mine` excludes `character`/`scene_asset`/`cover_asset` by construction — that dialog's category dropdown and flat-params editing model can't represent a character/scene's structured `reference_assets`, and re-filing one into `scene`/`lens`/`style`/`other` there would silently corrupt it. Those three categories are maintained only from their own dedicated pages (`/create/characters`, `/create/scenes`) or, for a cover, the one shared "另存为可分享技能" dialog (`components/studio/save-cover-as-skill-dialog.tsx`'s `SaveCoverAsSkillDialog`, taking the succeeded job's `output_asset_id`) that `job-progress.tsx`, `inline-image-result.tsx`, and `inline-video-result.tsx` all mount for an `asset_kind=cover` / `video_asset_kind=cover_video` result — never add them back to `CATEGORIES` in `manage-skill-dialog.tsx` or `create-skill-dialog.tsx`.
18. **Video creation has the same per-draft version history as image creation now — there is no more "material only" resume, and clips can auto-continue from each other's last frame.** `VideoGenerationStudio`'s `initialDraft`/`draftId` is a full resume, exactly like `ImageGenerationStudio`'s: every later submit reuses the same `draftId` (`GenerationSubmitInput.draftId`), and `GenerationVersionHistory` lists every *visible* job filed under it (see the table row above for its video-thumbnail rendering, the "当前" badge on `applied_job_id`, and 设为当前 / 删除). **`VideoGenerationStudio` and `script-clip-studio.tsx` lock the shell's "生成我的版本"** (`studio-submit-busy.ts`) while the HTTP submit is in flight, AI polish is `pending` (`PromptPolish.onPendingChange`), or any known job under the draft is still non-terminal (`created`/`queued`/`submitted`/`running`/`awaiting_input`) — picking an older succeeded version does not unlock it. Image / audio do not use this gate. `recent-draft-card.tsx`'s video 编辑 icon (`isVideoCreationOperation` + `videoCreationStudioHref`, `lib/video-draft.ts` — now the same shape as `lib/image-draft.ts`, no more "material" vs. "reopen" asymmetry) reopens the exact draft instead of seeding a brand-new `video_to_video` session; `create/new/page.tsx` resolves `?draftId=` into `initialDraft` for `operation === 'text_to_video'` the same way it already did for `text_to_image` (a `video_to_video`/`image_to_video` draft — remix, a raw material-editing entry — still has no independent "resume" shape of its own). Resume preview prefers `?jobId=` > `applied_job_id` > `latest_job_id`. One deliberate asymmetry survives on purpose: resuming does **not** auto-attach the resumed job's own output as the next submit's reference upload the way `ImageGenerationStudio`'s draft-resume effect does for `image_to_image` chaining — silently turning a plain prompt tweak into a `video_to_video` job on every resume would be a surprising default. `InlineVideoResult`'s explicit "基于此视频继续创作" button (`handleUseAsReference`, same shape as image's `handleUseAsReference` but never automatic) does that instead, only on click. Both studios still accept a `linkEpisodeId` prop, forwarded straight into `useGenerationSubmit`'s `submit()` call; a succeeded standalone video also offers "关联到剧集" after the fact (`LinkEpisodeDialog`) — see `zaolang-editor-drama` invariant #17 for what that does server-side. **Shot continuity is manual, and the automatic version is gone.** `VideoGenerationStudio` still declares `continuitySourceAssetId` so a stale `?continuityAssetId=` deep link does not 500, but nothing reads it: no code under `front/src/` calls `POST /v1/assets/{id}/frame` any more, and the breakpoint chip deliberately no longer emits the param (`script-breakpoint.test.ts` asserts it). An author who wants consecutive script clips to connect end to end switches the reference-mode panel to `frame_images` and picks the frames themselves. Don't re-add an on-mount auto-fill: it silently spent a request and pre-committed the author to a reference mode before they had chosen one. The `remixPage.continuityApplying` / `continuityApplied` / `continuityFailed` / `continuityRemove` keys are now dead in all three catalogues.
19. **Image and video creation never navigate to `/jobs/[jobId]`; audio still does.** `ImageGenerationStudio`/`VideoGenerationStudio` both pass `useGenerationSubmit` an `onSubmitted` callback (the two callers that do) instead of leaving it `undefined`, so a successful submit sets local `activeJobId`/`activeJobSeed` state and renders `InlineImageResult`/`InlineVideoResult` in `GenerationStudioShell`'s `previewSlot` instead of `router.push`-ing away — `AudioGenerationStudio` never passes this callback and keeps the original navigate-to-`/jobs/{id}` behavior unchanged. Every job filed under the same `Draft` (reused across "continue refining" submits via `GenerationSubmitInput.draftId`, resolved against `input.draftId` before falling back to `pendingDraft.current`) shows up in `generation-version-history.tsx`, which merges a fresh `GET /v1/generation-jobs?draft_id=` fetch with whichever job is currently streaming so the version currently generating is live without a second poller. Each studio's own "用作参考继续微调"/"基于此视频继续创作" re-fetches that version's output asset(s), **replaces** (not appends to, for the image side; video appends since it usually already has other references) `uploads`, and pre-fills the prompt from `GenerationJobResponse.prompt` — the same `draftId` carries forward, so this becomes the next version under the same draft rather than starting a new one. **Clicking a version in the history strip does the same prompt fill** (`selectVersion` → `promptFromVersion(job)` in `generation-version-select.ts`; video also aligns `duration_seconds` / `video_asset_kind`). That `job.prompt` is the submitted `request_json.prompt` (client polish accepted before submit), never the planner-enhanced text in `JobEvent.GENERATING`. A draft resumed via `?draftId=` (`create/new/page.tsx`'s `initialDraft` prop, or the collection library's/script studio's draft cards and breakpoint chips, which link to `/create/new?mode={image,video}_creation&draftId={id}` instead of `/publish/{id}` — see `library-tabs.tsx`'s `draftResumeHref`) fetches `?jobId=` then `applied_job_id` then `latest_job_id` once via `useResource` before seeding `useJobStream`, rather than starting the stream with a `null` initial job. This "always land back in the studio, never `/jobs/[jobId]`" rule extends to notification click-through too: `job_payload` (`zaolang-generation-jobs`) puts `draft_id` on every job notification's payload, and `notification-format.ts`'s `targetHref` routes there via the `{image,video}CreationStudioHref`/`is{Image,Video}CreationOperation` helpers (`lib/{image,video}-draft.ts`, shared with `draftResumeHref`) whenever the job's operation is an image- or video-creation one and a `draft_id` is present — otherwise (no draft, e.g. a sandbox-originated job, or an audio job) it still falls back to `/jobs/{id}`. The leftover `/jobs/{id}` URL itself follows the same split: `jobs/[jobId]/page.tsx` `redirect()`s an image- or video-creation job that has a `draft_id` to `{image,video}CreationStudioHref(draftId, jobId)` (the `jobId` keeps that attempt selected); episode posters (`generatedVideoDetailHref`) and the publish page's `GoBackLink` emit the draftId-only studio href and never `/jobs/{id}` for those operations. **A notification href is `draftId` + `jobId`**; draft cards stay `draftId`-only and resume `latest_job_id`. Do not fold `returnTo` into either. The studio prefers `?jobId=` so a retry's queued/succeeded toast opens that attempt, not the first failed one (`submit()` also advances `Draft.latest_job_id` — see `zaolang-generation-jobs`). Same pathname `/create/new` + a query-only change does not remount a client studio, so `create/new/page.tsx` keys `CreateStudio` with `studioSessionKey` (`lib/studio-session.ts`): `draft:{id}|job:{jobId}` when a notification carries both, `draft:{id}` for a draft-card/breakpoint-chip resume, otherwise the script jump-out's `mode`/`assetKind`/`target*`/`subjectNameHint`/`linkBreakpointKey`/`continuitySourceAssetId`/`skillId` (the last three only matter for a "fresh", `draftId`-less session — two different unbound breakpoints or plaza recipes must not share a key). Do not `router.replace` a `draftId` onto the URL after submit — that would change the key mid-stream and tear down the live job. The jump-out's `returnTo`/`returnLinkKind`/`returnLinkLabel` trio (image-only — video's script jump-out is the breakpoint chip, which has nothing to jump back to) is written onto `Draft.params` (`return_to` / `return_link_kind` / `return_link_label`, via `draftReturnParams`) on first submit; when the URL has no trio, the page restores it from the fetched draft through `readDraftReturnContext` + `sanitizeReturnTo` (exact `/create/characters` or `/create/scenes`, or a `/create/script/` prefix). A pre-existing draft without those keys still remounts onto the right session but has no return button. "Never navigate to `/jobs/[jobId]`" cannot mean "never let the author answer a follow-up question" either — `inline-image-result.tsx`/`inline-video-result.tsx` render `job/awaiting-input-panel.tsx`'s `AwaitingInputPanel` in place whenever the active job (and, for image, a historical side/back `completionJob`) is `status === 'awaiting_input'`, the same component `job-progress.tsx` uses on the standalone page. This exists as defense in depth even though every image-asset-kind (`character`/`scene`/`cover`) graph now turns the generic `planning` node's clarify off entirely (see `zaolang-generation-jobs` invariant #21) — a `GENERAL` image or video job's plain `planning` node still has it on by default, so it can legitimately suspend.
20. **A scene plate whose polish still has an unanswered required question cannot be submitted.** `ImageGenerationStudio` folds `PromptPolish.onBlockedChange` into `canSubmit` (only while `assetKind === 'scene'`) and swaps the composer `hint` for `remixPage.scenePolishBlockedHint`. This is deliberately *not* the job-side `awaiting_input` mechanism (invariant #18/#19): asset-kind graphs turn the `planning` node's clarify off precisely because the image studio cannot recover a suspended job, so the scene coach asks **before** submit, inside the polish panel, where the author is already looking. The gate can only ever engage after the author has actually clicked "AI 润色" and the coach returned a `required` question — going straight to 生成 is untouched, which is what keeps this from blocking someone who just wants a quick image.

## Extension Points

- **Add a page**: create a directory under `(site)/` (RSC renders server-side by default, fetching via `lib/api/server.ts`) → split interactive pieces into `'use client'` components → add trilingual copy to `src/i18n/messages/*.json` (all three files) → add it to the command palette's navigable items → add it to the visual and accessibility suites' page lists (`e2e/visual.spec.ts`, `e2e/a11y.spec.ts`) **unless it's flag-/sign-in-gated** (see invariant #14 — `/studio-editor/{cutId}`, `/create/script`, `/create/script/{episodeId}/clip`, and the two canvas routes are the existing exceptions). The canvas is the one place this checklist is genuinely **unfinished** rather than exempt: neither `/create/tools/canvas` nor `/canvas/[canvasId]` has a command-palette entry, so 「无限画布」 is reachable only from the `/create` tool card — worth adding when someone next touches that palette. A chrome-less full-screen surface belongs under `(studio)/` (with `StudioAuthGate`), not `(site)/`.
- **Change discover filtering/sorting**: `TagFilter` / `DiscoverSort` write `q`/`tag`/`sort` via `Link`; the default `popular` is omitted from the query. The Hero is a separate popular request and ignores the wall's query — do not slice the wall to hide Hero tiles. Contract: `zaolang-discovery-search`.
- **Add a shared component**: place it in `components/ui/`, merge classes via `lib/cn.ts`, implement every state, keep it keyboard-reachable.
- **Modify the API client**: errors are always `ApiError` (carrying the backend error code) — never parse a response body inside a component.
