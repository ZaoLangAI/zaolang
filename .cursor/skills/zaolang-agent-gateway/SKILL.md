# Agno Agent Gateway & LLM Access

## Scope

Agents own **judgment** (safety, planning, quality, routing selection) or **assisted generation** (copy: titles/descriptions/tags for a work about to publish, or polishing a scene description — never a pass/fail verdict); providers own **production** (images, video). Judgment and assisted generation are bridged by `router.py`'s hard capability/tier/enablement filtering plus the `intent_router` agent's LLM-driven selection: filtering is code, choosing is the model.

For the failover pool, MiniMax H3 contract details, `node_id` write-back mechanics, and prompt/model-binding, see [reference.md](reference.md) — this file covers the routing core (invariants #1–9) that almost every change in this skill touches.

## Invariants

1. **The hard filter is code; the choice is the LLM's — there is no fallback formula.** `router.route()` first filters out candidates that are physically or commercially unusable (capability unsupported, duration/aspect/reference-mode unsupported, provider disabled, over-budget latency, already failed once this job, and — since `MediaGenerationKind` — an `edit`-class video model on a request carrying no video source, `edit_model_requires_video_source`) in code. **Resolution is adapted, not hard-filtered, when the candidate can honour a strictly lower studio tier (or, as a last resort so the job does not die, its lowest tier)** via `adapt_resolution_tier` — never raise 1080p to 2K; `resolution_not_supported` only when that candidate's `resolutions` map to no studio tier. Remix still omits `resolution`. Costing and the provider call use the adapted vendor literal; `request_json` keeps the user's ceiling. Only candidates that survive get passed to `intent_router.select_provider()` together with each one's model name/success rate/latency/cost — whichever the LLM returns is what gets used, and `reason` is its stated rationale. Soft preferences (e.g. prefer a cheaper video-edit / compile model such as `wan2.7-videoedit` when `operation === video_to_video` and a video reference is present) live only in `SELECT_PROVIDER_SYSTEM_PROMPT` — never as a score or hardcoded pick in `router.route()`. **When the LLM is unavailable, degraded, or picks a provider outside the eligible set, `route()` returns `selected=None` (`reason="llm_selection_unavailable"`) directly — it never falls back to any weighted formula or ranking rule.** The old `quality/latency/cost/reliability` weighted formula and the `routing_weights` config have been removed; don't intuitively add them back. `tests/fake_llm_gateway.py`'s `_intent_router` still picks the lowest `effective_cost_micro_usd` and deliberately does **not** fold the remix preference into a formula. **"Report an upstream error, then switch providers" is already the default behaviour, not something to add**: a submit/poll failure (`aihubmix_media.py`/`dmxapi_media.py` classify it as `PROVIDER_TEMPORARY_FAILURE`/`PROVIDER_INVALID_RESPONSE`/`PROVIDER_TASK_FAILED`) takes the workflow's `retry` port back to the `route_score` node (`app.workflows.nodes.execute_route_score`), which adds the just-failed provider to `exclude_providers` (`tried_providers`) so the next `route()` call hard-filters it out (`filter_reason="previously_failed_this_job"`) and the LLM re-selects among whatever is left — only `MISSING_REFERENCE` (a user-input problem, not the provider's fault) and the sandbox-only synchronous-poll `PROVIDER_TIMEOUT` skip this and fail straight away. This exclusion is scoped to the one job; a provider currently failing across other jobs is not yet proactively avoided on a brand-new job's first attempt — that would be a cross-job circuit breaker, a deliberately separate, not-yet-built concern (see invariant #3's blended `success_rate`, which is a slow-moving signal, not a real-time breaker). **One narrow, deliberate exception**: `POST /generation-jobs/{id}/retry` (`zaolang-generation-jobs` invariant #24, `back/app/domain/jobs/fast_retry.py`) reuses this exact same `tried_providers` mechanism across the job boundary, but only for the one job being retried — it seeds the brand-new job's `ctx.state["tried_providers"]` with whatever failed on `retry_of_job_id` before jumping straight to `route_score`, gated on that having been a genuine provider failure (not a safety rejection, not a routing dead-end that never called a provider, not a quality rejection). This is still not a cross-job circuit breaker: it doesn't touch `ProviderStat`/`success_rate` or affect any other job, and no scoring/weighting code was added to `router.py` — it's the same "already failed once, exclude it" rule, just handed one extra `job_id`'s worth of history at start time instead of accumulating it live. **A second, equally narrow exception**: `GenerationParams.forced_model` (the image/video studios' "指定模型" advanced-setting picker, backed by `GET /v1/generation-jobs/models`) lets the *user*, not the LLM, make this one request's choice — `route()`'s `forced_model` parameter still runs the exact same hard filter unchanged, then picks deterministically (lowest `provider` name) among whatever survives that also carries the matching `model_or_workflow`, skipping `intent_router.select_provider()` entirely rather than narrowing its candidate list. This is not a formula either: it is a one-off, explicit hand-off of the choice itself to a human for this one request, never a computed score, and it degrades the same hard-failure way as everything else here — no candidate matching the forced model is `reason="forced_model_unavailable"`, with no silent fallback to the normal LLM-driven pick.
2. **Candidate info is for display and input only, never for deciding.** `Candidate`'s `success_rate`/`avg_latency_ms`/`effective_cost_micro_usd` — plus `estimated_cost_micro_usd` (this request's own duration/resolution/reference-count pricing) and `cost_is_estimated` (true when both numbers come from the built-in prior rather than operator-configured prices), all serialised into the selection payload by `router._candidate_payload` — are context fed to the LLM, and also the fields shown in admin's "step-through candidate replay" — but no code path is allowed to sort or weight by these fields to pick a winner. Ranking authority belongs to `intent_router` alone. **`model` (`capability.model_or_workflow`) rides along as the same kind of display-only context** — it is the only way the agent can tell candidates apart by real identity, since `provider` is an opaque catalog key (`f"{endpoint_id}:{tag}"`). `quality_prior` is a flat system default (`media_endpoints._QUALITY_PRIOR`, currently 0.75 for every candidate, not a per-model score) — real quality judgment is delegated entirely to the LLM's own knowledge of `model`, per `SELECT_PROVIDER_SYSTEM_PROMPT`; don't add a hardcoded "model name → quality score" table in code, that would just be routing logic pretending to be data.
3. **`effective_cost_micro_usd` bakes in a fixed 1.2× failure-retry amplification.** `success_rate` blends real `ProviderStat` attempts with the conservative 0.8 prior via additive (Beta) smoothing weighted by `PRIOR_PSEUDO_SAMPLES` (currently 8 virtual trials) — not a hard sample-count cutoff. A handful of real failures pulls the number down well before dozens of samples would have accumulated; `attempts=0` still reads as the neutral prior.
4. **Every candidate's elimination reason must be persisted** to `ProviderAttempt` / the decision record — admin's "step-through candidate replay" depends on it.
5. **Agent output isn't fact until it's persisted.** Agents can only call domain services through the `tools.py` whitelist — never give an agent a raw session or arbitrary SQL.
6. **There is exactly one gateway mode: real calls, or an error.** No stub/auto mode exists in production code — an unbound model, no configured endpoint, or every eligible endpoint failing all raise `ProviderTemporaryFailure` (503) immediately; there is no silent fallback to fabricated data. `back/tests/fake_llm_gateway.py` plus an autouse fixture in `conftest.py` keeps the test suite deterministic and offline by monkeypatching `llm_client.complete`/`stream_complete`, without adding any branch to production code. Tests exercising the real gateway's own plumbing opt out with `@pytest.mark.live` (an actual network call) or `@pytest.mark.real_gateway_seams` (mocks `_call_gateway`/`_stream_gateway` to test `complete()`/`stream_complete()`'s own failover/circuit-breaker/error logic).
7. **Every call writes an `AgentRun`**: model, token usage, latency, whether it degraded, and `input_json` (`{system_prompt, user_prompt}`, used for admin per-node replay). Admin's agent tooling is built entirely on this table.
8. **Response normalization can never be skipped**: strip `<think>...</think>` and `reasoning_details`, extract the outermost JSON from free text, retry-and-repair before degrading on a parse failure. A reasoning model's thinking tokens count against `max_tokens` — **budget generously**, or `content` comes back empty with `finish_reason=length`. **A caller's `max_tokens` to `run_agent`/`run_agent_stream` (`back/app/agents/base.py`) is a floor, not an override**: `max(max_tokens, binding.max_tokens)` — a bound endpoint's own larger declared `max_output_tokens` (`EffectiveBinding.max_tokens`, see `_binding_max_tokens`) always wins over a smaller slot constant such as `copywriter.SCRIPT_MAX_TOKENS`/`ENHANCE_MAX_TOKENS`. That constant only matters as a floor for an endpoint that hasn't declared its own ceiling (or declared a smaller one) — it must never artificially shrink a well-configured model's real budget down from what an operator actually configured in `/admin/models`, which is exactly what let a real reasoning model burn its entire (needlessly small) first-attempt budget thinking and come back with zero completion tokens.
9. **Secrets are managed only through the dedicated masked `/admin/models` API** — never the general config API, the JSON editor, logs, or a prompt; environment variables are for local seed bootstrapping only.
10. **Transport is stream; the caller contract is not.** Formal `complete()` / `run_agent()` still hand the caller one JSON `LlmCallResult` / `AgentOutcome`, but the wire call is `_stream_gateway` assembled under `STREAM_WALL_CLOCK_TIMEOUT_SECONDS` (600s). Thinking deltas reset the idle `timeout_ms` timer (that is what stops glm-5.3-flash from dying at 30s of silent think) but do not reset the wall clock. A thinking-only wall-clock / transport timeout on `stream_complete` still gets one same-endpoint budget-expansion retry; `is_usable` failing on recovered thinking *or* on already-yielded content (decoy / truncated JSON) also gets that retry — still no mid-stream failover to another endpoint. `retry_nudge` is appended as a user turn on the retry so a model that spent the first budget thinking is told to emit the payload. A retry that still has no usable text leaves `result.text` empty for the caller to mark `parse_ok=False` rather than raising "LLM 网关不可用: TimeoutError". Prompt polish additionally requires an enhance-shaped object (`prompt` + `detail_level`) — the first `{...}` in a reasoning trace is often a harness decoy (`{"answer":"$your_answer"}`) and must not count as success. `run_agent_stream()` remains the HTTP SSE turn (`thinking` / `delta` / `complete` / `error`) for 文案创作, prompt polish, edit-plan, and admin debug-chat. Once a chunk has been handed to `on_chunk` (or yielded from `stream_complete`), there is no mid-stream failover. **Admin「验证有效」stays a non-streaming ping:** `call_gateway_once` → `_create_completion` (`create()`), 16 tokens, no failover/breaker/stats. Do not convert that path to stream. Thinking is persisted on `AgentRun.thinking_text`, never stuffed into `output_json`.
11. **The Quality agent judges metadata, and metadata never includes the media.** `output` carries technical fields only (width/height, provider, `partial_output`, `upstream_status`) — the agent can't see the image or video, and `SYSTEM_PROMPT` says so explicitly, because "I cannot see the actual content" is otherwise the single most likely way for a model to fail every job. Two things in particular are **not** failure signals: a missing width/height, and a duration that disagrees with prose in the prompt — a shot card's 「0—3秒」 is narrative text, not a delivery spec, and the video is generated from the form parameters. `duration_ms` was removed from `output_summary` for exactly this reason (`tests/unit/test_quality_duration_gate.py` is the regression test). When adding a field to `output_summary`, ask whether a model could read it as a defect; if so, say in the prompt that it isn't one.

## Extension Points

- **Add an agent**: add an executable role/node → create an `AgentProfile` in `/admin/agents` and pick a provider and model → call domain services only through `tools.py` → add a matching dispatch branch to `back/tests/fake_llm_gateway.py`'s `_dispatch()` so the offline test suite has a deterministic response for it.
- **Add a new system prompt to an existing role (a sibling slot)**: a role can hold several prompts that don't share instructions — most are called directly from code (e.g. the `copy` role's `suggest` (work copy), `enhance` (prompt polishing), `clarify` (a pre-generation follow-up question, letting the short-video studio decide whether it needs more info from the user before submitting), and `script_draft`/`script_revise` (streaming — full script generation/revision, see invariant #10)) — but a slot can also be reached exclusively through a workflow node's `AgentBinding`, one node type per slot: `planner`'s `asset_plan` (the `asset_planning` node) sits alongside its `default`/`clarify` slots (the `planning` node) this way, rather than through a thin domain wrapper. Add a `PromptSlot` to `back/app/agents/slots.py`'s `PROMPT_SLOTS[role]` → add the constant + function in the matching agent module, `run_agent(..., slot=your_slot)` (or `run_agent_stream` for a streaming reply) → add a starting template in `agent_skills/templates.py` → either add a thin wrapper function under `back/app/domain/<domain>/` (named for the caller's role semantics — don't reuse a domain function already consumed by another frontend) or a new node type with an `AgentBinding` pinning it to this slot (see `zaolang-generation-jobs`). For non-`copy` roles the new slot appears automatically as a tab in `/admin/agents`'s `AgentSkillEditorDialog`. **Copy no longer shows slot tabs** — the editor infers `enhance` vs `suggest` from `default_for_asset_kind`; new copy slots stay callable from code but are not operator-editable until that inference is extended.
- **Add an asset-kind sibling template on an existing slot**: when the same slot needs a specialised starting prompt per `asset_kind` (today: `copy`'s `enhance` for `character`/`cover`/`scene`), do **not** open a new slot. Add a first-class constant on the agent module (`ENHANCE_SYSTEM_PROMPT_*`) that states that kind's job and hard rules — share `_ENHANCE_CONTRACT` for the JSON wire shape, do not append a footnote onto the generic coach → one `SKILL_TEMPLATES` entry (same `slot`, distinct `key`/`label`) so `/admin/agents` "fill from template" can load it → seed a dedicated `AgentProfile` with `default_for_asset_kind` (see `ensure_default_enhance_asset_agents`) → put the same constant in `enhance_prompt`'s fallback dict. The published `AgentSkill` is what runs; the constant is only the seed/fallback. `seed.sync_seeded_copy_agent_prompts` republishes those constants onto the seeded keys (`default` / `enhance-character` / `enhance-scene` / `enhance-cover`) when the active draft still opens like a factory prompt — an operator's own wording is left alone. Changing `ENHANCE_SYSTEM_PROMPT_CHARACTER` without reloading a hand-edited `enhance-character` in `/admin/agents` will not update production polish. Video-kind variants (`character_action`/`transition_video`/`cover_video`) follow the same fallback-dict pattern but are not yet separate templates or seeded profiles.
- **Add a role preset**: add an entry to `presets.py`'s `ROLE_PRESETS` (choose `judgment` or `assist` — binding works the same either way, only the semantics differ: whether it produces a pass/fail verdict) → add a starting template in `templates.py` while you're there → confirm it can actually be invoked by some node type (a dedicated node type, or `custom_agent`), or an agent built from it will never run. Presets are a code catalogue, not a table — adding one is still an engineering change, which is exactly the point of "roles can only be chosen from presets."
- **Add a tool for an agent**: add it only to `tools.py`, with a narrow signature (explicit params, explicit return) — never expose the session.
- **Add a fake provider for tests**: construct a `ProviderCapability` and monkeypatch `build_catalog` only inside `back/tests` — production `router.py` never registers a fake.
- **Add a real media provider (config-driven, no code change)**: go to `/admin/models` and add a `kind="media"` endpoint, pick its **interface protocol** (OpenAI / MiniMax / MiniMax V2 / DashScope / DMXAPI / fal are implemented; other options are disabled), fill in the model id, then check the input/output modalities it supports; capability tags are derived automatically by `capabilities_for_modalities`, and `router.build_catalog(session)` expands it into the candidate catalogue by capability on the next routing pass. An unimplemented protocol never enters the catalogue. If the same credential needs different models for different capabilities, configure multiple endpoints. The form's "service provider" picker (`VendorModelPicker` in `llm-providers-panel.tsx`, backed by `model_catalog.py`) offers a known-model shortcut for AiHubMix/DMXAPI/秘塔/fal.ai that pre-fills base URL/protocol/modalities — purely a convenience, "custom" still works exactly as before it existed. A new `GenerationProvider` implementation is only needed when the target vendor's HTTP contract is neither OpenAI-compatible generations/speech, the existing MiniMax H3 native-video path (`protocol=minimax`), official MiniMax Video V2 (`protocol=minimax_v2`), DMXAPI's `/v1/responses` envelope, nor fal.ai's queue (`protocol=fal`, e.g. a future standalone ComfyUI `POST /prompt` + `GET /history` adapter). Add its model(s) to `model_catalog.VENDOR_MODEL_CATALOG` too, so the picker offers them. Do not reuse `protocol=minimax` with a Metaso or fal base URL — those are different HTTP contracts.
- **Change selection logic**: never add sorting/weighting code to `router.py` — that's a deliberate gap (invariant #1). To change the criteria for "which provider wins," edit `intent_router.py`'s `SELECT_PROVIDER_SYSTEM_PROMPT` (or the admin-publishable `AgentSkill` version), and sync `tests/fake_llm_gateway.py`'s `_intent_router` deterministic branch, or every routing test changes behavior under the fake gateway.
