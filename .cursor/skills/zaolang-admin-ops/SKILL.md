# Admin Operations Domain

Security boundary, RBAC, shell, and component family: see `zaolang-admin-console`. This skill covers what each domain **does, where its data comes from, and what must not change.**

## Invariants

1. **Health probes only report, never repair.** They check Postgres / Redis / MinIO / Celery liveness, backlog and consumption rate across every queue in `QUEUE_NAMES` (incl. `media_analysis`), the Alembic version, and **LLM gateway connectivity and current mode**. `back/app/workers/celery_app.py:QUEUE_NAMES` is ground truth for the queue list — sync the health page and the Makefile's `dev-worker -Q` when adding one. Probe queries must run inside `begin_nested()` — a failing probe that poisons the transaction takes the whole page down with a 500.
2. **Forced job termination still goes through the state machine** (`state_machine.transition`), never a direct status UPDATE. Terminating must release the reservation, or it creates a dangling one. **Hitting an in-flight `AsyncProviderTask` synchronously attempts `async_tasks.cancel_upstream()` within the same request** to notify the provider; a failure (capability missing from the catalogue, `provider.cancel()` erroring or timing out) doesn't block the status transition, only logging a `system_log.emit`; the audit's `after_json` records `upstream_cancel_attempted`/`upstream_cancel_succeeded` for later review.
3. **Requeuing a stuck job never charges a second reservation**: `requeue` reuses the original job and its original reservation — no new job, no new reserve.
4. **Full-pipeline replay is read-only**: `JobEvent` + `ProviderAttempt` + routing-candidate decisions are for display — never "just tweak it while you're there."
5. **`ProviderStat` is a cumulative counter** — a new row must explicitly initialize `attempts` / `successes` / `total_latency_ms` / `total_cost_minor` to 0; relying on column defaults means they're still `None` before flush and `+=` blows up.
6. **A moderation decision must leave a human trace**: `claim` then `decide`, always recording who, when, and why. **"Reject" means hide (reversible); tombstone is a separate, high-risk, terminal action** — don't conflate them. **Exception: `generation_job` subjects (incl. sandbox runs)** — their output was never published, so `decide` only appends a `ModerationResult`, never a hide/tombstone.
7. **Tombstone/hide/restore semantics are fixed**: hidden can be `restore`d; a tombstone is terminal (see `zaolang-domain-licensing-lineage`).
8. **Manual ledger adjustments only ever append**, with a mandatory reason, a second confirmation, and an audit entry (see `zaolang-credits-billing`).
9. **Reconciliation and dangling reservations are two different metrics** — their numbers disagreeing is by design, not something to "fix" into alignment.
10. **`seed` / `reset` must be refused in production**, guarded by a dedicated test. A backup restore must leave a `BackupRecord`.
11. **Announcements split into site-wide and maintenance categories**; maintenance announcements must be prominently shown at the top of the consumer app.
12. **The product sandbox is tracked in job ops and content moderation but never charges credits.** See `zaolang-generation-jobs` invariant #14. Never revert the product sandbox back to an in-process `dry_run`.
13. **Editing `defaults.py`'s seeded graph shape never touches an already-published `(operation, asset_kind)` row.** `ensure_default_templates` only seeds a bucket that has no active template yet, so a code change there is invisible to every environment that already ran the seed once (any local/test/production database past its first boot). Ship a data migration alongside the code change — read every affected active row's `graph_json`, patch it in place, write it back (see `zaolang-generation-jobs` invariant #21 for a worked example: disabling the generic `planning` node's follow-up question on every `character`/`scene`/`cover` template). Rewrite the row directly rather than going through `publish()` — these rows are auto-seeded, not an operator's hand-edited history worth a new version for.

## Extension Points

- **Add a health probe**: add an item to `observability.py`'s `/health` → add a card to `health-cards.tsx` → a failed probe must degrade to "unknown," never throw.
- **Add a statistics metric**: a daily trend goes into `zaolang-admin-statistics` (SQL `date_trunc` + zero-fill for empty days); a snapshot keeps using the older ops endpoint. All lists use cursor pagination.
- **Add a bulk operation**: the backend accepts a list of IDs and **runs the same domain function per item** (preserving every single-item validation and audit entry) — don't write one big UPDATE for performance's sake.
- **Add an ops page**: follow the four-step checklist in `zaolang-admin-console`.

## Verify

```bash
cd back && conda run -n zaolang pytest tests/integration/test_admin_ops_runtime.py tests/integration/test_admin_ops_domain.py tests/integration/test_admin_ops_platform.py -v
make test-e2e
```

Manual path: after `make seed`, open `/admin` — system health should show all four dependencies green, and user ops should find the suspended `driftwood`. `make seed` creates login accounts and the system-level defaults (agent nodes/profiles, workflow templates, feature flags) plus one system-default exception: a platform-curated short-drama `CreationSkill` catalogue (`skill_library_service.ensure_catalog_skills`, `back/app/domain/skill_library/catalog.py`), owned by the dedicated seed account `zaolang_studio` — not a stand-in for real user-submitted content, same category as the workflow templates next to it in this list. Those rows are written straight to `PUBLISHED`/`PUBLIC` with no `moderation_queue_items` entry, so they show up in the skill library console with `reviewed_by_user_id`/`reviewed_at` both `None` — that is expected, not a missing audit trail, since nothing was ever submitted for review. Beyond that one exception, `make seed` still plants no other business content, so job ops, credit ops, moderation, the style gallery, and agent-degradation views stay empty until real jobs/works/reports exist; verifying those pages needs actual data (drive a job through the API, or `tests/integration/test_admin_ops_*.py`'s fixtures) rather than a fresh seed.
