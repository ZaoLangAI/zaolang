# Creation Library

**Scope**: user-authored and seeded `CreationSkill` rows — prompt templates plus the character, scene, and prop asset cards (same table, distinct `category`), their variants/entries, relation graph, character voices, share/review/sell lifecycle, and studio/workspace apply.
Not here → `zaolang-admin-ops` (review, takedown), `zaolang-credits-billing` (unlock charges), `zaolang-agent-gateway` (`agent_skills`), `zaolang-data-model` (`sk_` ids), `zaolang-canvas` (workflow `variables`), `zaolang-generation-jobs` (`execute_skill_context`, job-output write-back into rosters).

## Invariants

1. **Asset card storage & endpoints**: Characters, scenes, and props are `CreationSkill` rows (`character` / `scene_asset` / `prop_asset`), with metadata at `params_json["character"|"scene"|"prop"]`. Edit them only via `/v1/characters|scenes|props` (+ looks/variants routes): `/v1/skills` create/edit returns 422 on all three categories. The skill detail (`/v1/skills/{id}`) strips any leftover `reference_assets` from `params` (`_public_params`) and, once unlocked, returns signed `asset_variants` + `anchor_asset_id` instead.
2. **Lifecycle & moderation**: Create → `DRAFT`/`PRIVATE`. `publish()` runs the `skill_moderation` gate, sets `PENDING_REVIEW`/`PUBLIC`, and reopens the single moderation queue row (subject `skill`); re-publish is a no-op. Public reads check `status == PUBLISHED` only (`service.py:get_usable`).
3. **Auto-withdraw on edit**: A content edit on a non-`DRAFT` row drops it to `DRAFT`/`PRIVATE` and closes the open queue item (`withdrawn_by_owner`), same as `withdraw()` — all card services go through `service.py:withdraw_after_edit`; `/pricing` never does.
4. **Publish consent rules**: Characters publish only via `POST /v1/characters/{id}/publish` with `portrait_consent: true` (stamps `portrait_consent_at`); `/v1/skills/{id}/publish` rejects them. Scenes and props require no portrait consent.
5. **Uniqueness**: One character name per owner (DB partial index `uq_creation_skills_owner_character_title` + `_require_unique_character_name`, 422 on `name`). Scene and prop names are not unique.
6. **Paid unlock**: `access_credits > 0` requires `marketplace_enabled` and `<= max_access_credits` (`access.service.normalize_access_credits`). Detail `params` is `{}` until `viewer_unlocked` (owner/free/grant). `/unlock` honours `Idempotency-Key`.
7. **Usage counting (`POST /apply`)**: `POST /apply` is the only usage counter (asserts unlocked). The plaza dialog never calls it; the studio `?skillId=` seed does. Server re-fold and auto-matchers (`apply_matching_format_skills`, `list_drama_candidates`) never count or charge — matchers only take free rows owned by the catalogue account (`_planted_catalog_rows`), never a user's same-titled skill.
8. **Template folding & plaza CTAs**: Image-asset categories fold only `TEMPLATE_FOLD_KEYS`; `variables` never folds; empty `applicable_operations` = any, yet `isSkillMentionable` hides image-asset skills without declared ops. There is no standalone image studio: an image-only template is a style skill for the card workspaces — the plaza CTA links to `/create/{kind}?skillId=` (applied once there, preselected in the Creation slot panel); an asset card's CTA links to video creation (preselected as a reference only when the viewer owns it, since `character_ids` / `scene_ids` / `prop_ids` must be caller-owned).
9. **Reference resolution & angle ranking (`back/app/domain/image_assets/reference_resolver.py:resolve`)**:
   - **Budget & ownership**: `character_ids` / `scene_ids` / `prop_ids` (≤4 each, caller-owned) merge into the shared 9-slot `reference_asset_ids` (explicit refs first, then characters, scenes, props).
   - **Selection & default subset**: Each card contributes its `character_ref_selection` / `scene_ref_selection` / `prop_ref_selection` item (`variant_id` for that look's default subset, `asset_ids` from the card/look, else 422), or `asset_variants.service.default_subset` (character: anchor if on default look or any look's `identity_portrait`, then sheet/views front→side→back, ≤3; scene/prop: variant's master then shots, else card's anchor, ≤2).
   - **Shot/emotion & camera-angle re-ranking**: Defaults are re-ranked by `asset_variants.service.ReferenceHints` from `reference_shot_size` / `reference_emotion` or the prompt's `"镜头："` line (`blocking.camera_language.parse_camera_text`): close shots lead with identity portrait + matching expression sheet; wide shots lead with sheet + views; close scene shots lead with shots before master. With a viewpoint (`reference_camera_side`/`reference_camera_height` or from `"镜头："`), angled images (sheet 0°, views, posed shots, masters 0°) are ranked by `camera.angular_distance` (`_angled_subset`: back shot leads with back view, reverse shot with reverse plate; close front shot still leads with portrait). Explicit `asset_ids` are never reordered.
   - **Auto-borrowed references & labels**: Borrows the target look's sheet for an expression job with no reference, or the target's approved identity portrait (`asset_variants.service.identity_portrait`) for any other character job with no reference — for an outfit change (non-default `target_variant_id` look or `character_outfit_label`), also borrows that look's approved sheet and `outfit_detail` uploads, falling back to the default look's sheet when there is no portrait (legend suffixes `reference_resolver.FACE_ONLY_ROLE` / `OUTFIT_ONLY_ROLE`, ≤3 borrowed). Writes server-only `target_look` `{name, description}` (client values popped) and `reference_labels` (`asset_variants.service.entry_label`, e.g. `角色「林夏」·婚礼·设定图`). Unlocked published cards' approved entries and covers are usable references (`skill_library.service.asset_is_usable_skill_reference`).
10. **JSONB immutability**: Never mutate `params_json` in place — `_payload` returns copies and writes go through `_set_payload`; otherwise SQLAlchemy silently skips the UPDATE.
11. **Variants, looks & entries (`skill_asset_variants` / `skill_asset_entries`)**:
    - **Variants (`skill_asset_variants`)**: One `is_default` per card, unique name; ≤48 looks per character card, uncapped for scene/prop cards. `presets_json` is enumerated and kind-checked by `asset_variants.service._check_presets` (look: `age_stage` `AgeStage` / `period` `ScenePeriod`; scene variant: lighting/weather/state/period; prop variant: `prop_state` / `period`; else 422). Free text lives in `attributes_json` (`_check_attributes`: look `outfit`≤20 / `state`≤40 / `scene_note`≤60 / `custom`≤8 key-values; scene/prop variant `custom` only; included in `moderation_texts`). A character look may link one owned scene card (`scene_skill_id`/`scene_variant_id`, SET NULL, `set_scene_link`; owner-only, dropped from public detail). `reference_resolver._target_look` writes these into `target_look`, and `prompt_builder._look_attribute_fragments` renders them into sheet/expression sentences.
    - **Entries (`skill_asset_entries`)**: Hold `entry_type`, `view`, `label`, `status`, and at most one `is_anchor` per card. Caps: ≤24 approved per look and ≤480 approved per character card (scene/prop cards: per-variant cap only) — exceeding a cap returns 422 (never evicts); candidates are uncapped until deleted. Both tables CASCADE with the skill and entries with their asset; a composite FK keeps an entry on its own card's look.
    - **Read projection**: `CharacterView`/`SceneView`/`PropView.reference_assets` is computed on read via `asset_variants.service.project` (anchor first; non-default look entries carry the look name as `label`); `params_json` stores no copy (dropped by migration `…_drop_reference_assets_mirror`). Legacy `(view, label)` calls translate automatically (`front` → `character_sheet`, `establishing` → variant `master`). `action_clips` (≤12 videos) stay in JSON and never enter `reference_asset_ids`.
12. **Seeded catalogue identity**: Matched by `(owner, title)` (`CatalogSkill.key` is not stored); owner = `catalog.CATALOG_OWNER_HANDLE` (`zaolang_studio`) for `make seed`, `app.scripts.ensure_catalog` and the `catalog_owner` test fixture. `ensure_catalog_skills` plants `PUBLISHED` rows unreviewed, never overwrites edits, and only backfills a null cover; a retitle plants a new row.
13. **Category visibility filters**: `list_mine` and default `list_public` exclude `IMAGE_ASSET_SKILL_CATEGORIES`; both (and every `content_type` / `category` filter) also exclude `service.HIDDEN_PUBLIC_CATEGORIES` (`cover_asset`). `COVER_ASSET` stays in `IMAGE_ASSET_SKILL_CATEGORIES` so legacy cover rows do not leak into templates. `/v1/skills` create/edit returns 422 on `cover_asset` (`_reject_character_category`), the catalogue has no cover rows, and planted ones remain readable by ID.
14. **Candidate vs approved status (`AssetEntryStatus`) & consistency verdicts**:
    - **Filing & approval**: Job write-back files into a filled slot as a `candidate` (`asset_variants.service.file_generated`); manual upload or legacy edit approves and replaces. `approve_entry` (`POST …/entries/{id}:approve` or PATCH `status=approved`) swaps the slot — the displaced entry becomes a candidate and transfers the anchor. Only approved entries can be the anchor (candidate anchor or demoting the anchor returns 422). Candidates appear only in the owner's `looks`/`variants`; `project`, `asset_ids`, `default_subset`, and public skill detail (`variant_views(approved_only=True)`) use approved entries only, and `set_members` leaves candidates untouched. On web, `features/asset-workspace/slot-panel.tsx` shows candidates beside the approved image with Approve ("定稿") / Remove ("移除") and Clear candidates ("清空候选（n）", `useAssetGraph` `deleteEntries`).
    - **Vision consistency verdict (`SkillAssetEntry.consistency_json`)**: Owner-only (omitted from `project`, `variant_views`, and skill detail), never copied by adjust/derive/flat-list edits (kept on move since it is the same row). Approving a `below` entry (`approve_entry`, PATCH, or `set_members`) stamps `owner_approved_at` on a new dict. Under `asset_consistency.mode=enforce`, write-back files a below-threshold generated image as a candidate even into an empty slot (`consistency_json.demoted`), so it never takes the anchor and Fill Missing ("补齐缺失") sees the slot as `candidate`, not missing (see `zaolang-generation-jobs` › `reference-asset-pipeline.md`).
    - **Identity portrait anchor**: A `character_portrait` job (`append_reference_asset(portrait=True)`) always files into the default look; once approved, it takes the anchor from no anchor or a sheet, never from another portrait (`prefer_portrait_anchor`).
15. **Scene variant matrix (`POST /v1/scenes/{id}/variants:matrix`)**: Implemented in `back/app/api/v1/scene_matrix.py` + `back/app/domain/scenes/matrix.py`. Caps: ≤4 values per axis, ≤12 cells per request. `dry_run` (default) returns each cell's status (`new` / `exists` = approved master / `candidate`) and the exact total (`quote_for` × new cells, checking balance + monthly cap like `quote:batch`). A submit refuses up front when the total exceeds limits, counts one `generation_submit` hit per job, and submits one job per new cell (single-image `scene_*` presets + `target_scene_id`, per-cell idempotency key `{key[:100]}:{sha1(cell)[:12]}`); write-back files each image under the variant matching its presets.
16. **Asset relation graph (`skill_asset_edges`)**: Joins two looks/variants or two images of one card, never across levels or cards; each level stays a DAG. Edges are owner-only metadata (no moderation, no `withdraw_after_edit`). Node positions are not persisted: the web canvas re-runs dagre layout on every load. Moving an image to another look re-parents the same row (`update_entry`), preserving its ID and edges.
17. **Adjust / derive (`POST …/entries/{entry_id}:adjust|:derive`) & version folding**: Implemented in `back/app/api/v1/asset_derive.py` + `back/app/domain/asset_graph/derive.py`. `dry_run` prices one image; submit creates the new look (when requested), its look-level auto edge, and the job in one transaction (idempotent replay checked before planning). Job params carry `source_entry_id` (reference 1 via `reference_resolver._source_entry_reference`), `asset_edit`, `asset_output_entry_type`, and `asset_output_mode=in_scene` (borrows the look's linked scene still). Write-back files an adjust like its source and always as a candidate (a version), and files a derive as the requested type, then `asset_graph.service.link_job_output` adds the image-level auto edge (`edit` for adjust). Versions are folded into one node in the web graph (`front/src/components/asset-graph/versions.ts`); `edit` is not a manually pickable relation.
18. **Character voices (`back/app/domain/characters/voices.py`, `back/app/api/v1/character_voices.py`)**:
    - **Types & caps**: Either `preset` (model + roster voice + only knobs listed by `model_catalog.voice_capabilities`) or `clone` (owned audio sample with active voice consent); ≤48 per card, unique names, one default (first voice; deleting it promotes the next).
    - **Access & unlock**: Owner-only management (no withdraw on edit, 404 for buyers on voice routes, graph, and previews). Voices unlock with the character card: unlocked skill detail/apply carries `voices` (`voice_view(public=True)` — never exposing the clone `sample`), looks keep `voice_id`, and a buyer's job may reference `voice_profile_id` while the card is published and public (`skill_library.card_is_usable_by`), with a clone's sample passing as a usable reference (`asset_is_usable_skill_reference`, audio branch) under the author's consent (`tests/integration/test_character_voices_api.py::test_unlocking_a_character_unlocks_its_voices`).
    - **Bindings, derive & preview**: Looks bind one voice (`voice_id` via `bind_looks` / look PATCH). `derived_from` creates a voice plus a `voice`-level auto edge (`relations_between`: age/emotion/scene(use)/params/custom). Jobs resolve `voice_profile_id` via `voice_resolver.apply_voice_profile` at submit (`forced_model`, `extra.voice/emotion/speed`, or clone sample reference). `:preview` submits a `target_voice_id` job whose output lands as the voice's preview; `voices:match` (`copy` slot `voice_match`) proposes a preset from enabled audio models' rosters without saving. Web UI lives on the Voices (`音色`) tab (`asset-graph-workspace.tsx`, `mode="voices"`, `inspector/voice-inspector.tsx`, `voices-panel.tsx`, `voice-form.tsx`), read-only `components/skills/unlocked-voices.tsx` on the skill detail dialog, and the `'character'` mode in `components/studio/audio-generation-studio.tsx`.
19. **Fill missing look slots (`POST /v1/characters/{id}/looks/{look_id}:fill`)**: Implemented in `back/app/api/v1/look_fill.py` + `back/app/domain/characters/fill.py`. A look's standard set comprises the card's identity portrait, the look's front sheet, four turnaround poses (`ORBIT_SLOT_AZIMUTH`: side 90°, back 180°, left 270°, three_quarter 45°; a legacy `side`/`back` view counts), and one expression grid (`DEFAULT_FILL_EXPRESSIONS`); only approved entries count, and candidate-only slots are never regenerated. Execution waves: portrait → front sheet → one `image_to_image` `camera_poses` job for missing poses (sourced from the look's approved 0° single figure, else its approved sheet with `camera_from_sheet`) → expressions. `dry_run` prices every wave (checking balance + monthly cap); submit checks the total and submits only the next wave (idempotency key `{key[:100]}:{sha1(look+slots)[:12]}`). Client re-calls after each wave (`front/src/components/characters/look-fill-dialog.tsx`, `front/src/features/image-assets/fill.ts:fillStep`).
20. **Multi-angle camera orbit (`POST /v1/{characters|scenes|props}/{id}/entries/{entry_id}:orbit`)**: `skill_asset_entries.camera_json` stores `{azimuth, elevation, distance}` on the grid in `back/app/domain/image_assets/camera.py` (8 azimuths × 4 elevations × 3 distances; 0 = front, 90 = subject's right, 180 = back / reverse shot). `asset_variants.service.entry_pose` reads `camera_json` or falls back to coarse `view` (`camera.from_view`; sheet = 0°). Each pose is its own slot (`slot_mates`): a character `view` per pose bucket (legacy `side` = 90° slot), and a scene/prop `shot` when posed (unposed shots accumulate). `:orbit` (`asset_derive.py` + `derive.plan_orbit`) submits one `image_to_image` job with one pass per pose (≤8, snapped and deduplicated), filed into the source's look/variant with an auto `camera` edge per image (`asset_graph.service.link_job_output`). A sheet source is led by a 0° front-figure pass that subsequent poses chain from (`camera_from_sheet`). Entry create/PATCH accept `camera` (`clear_camera`).
21. **Prop asset cards (`CreationSkillCategory.PROP_ASSET`) & scene panoramas (`AssetEntryType.PANORAMA`)**:
    - **Props**: In `IMAGE_ASSET_SKILL_CATEGORIES` and `ASSET_CARD_CATEGORIES`, payload `params_json["prop"]`, variants `kind='prop_variant'` (presets `prop_state` / `period` only; unified via `card_kind(skill)` / `CARD_NOUNS` / `_ENTRY_TYPES` / `_VIEWS` in `asset_variants.service`). Entry types `PROP_ENTRY_TYPES` (`master` / `view` / `shot` / `other`), uncapped variants, master-led `default_subset` ≤2, graph relations `PROP_RELATIONS`. Jobs use `asset_kind=prop`, `target_prop_id`, `prop_state` (`PROP_STATE_PRESETS`), `prop_ids` + `prop_ref_selection` (≤4), `AssetPass.PROP`, and write-back `_link_prop_output` (`GenerationJob.linked_prop_id`).
    - **Scene panoramas**: `AssetEntryType.PANORAMA` (scene cards only, one slot per variant). Never used as a reference (`default_subset` / `_angled_subset` / `master_or_anchor` / `scenes.service._promote_master` skip it, `set_anchor` 422s, `asset_graph.derive._source` refuses it for adjust/derive/orbit — cut a shot first, and `back/app/domain/image_assets/consistency.py:resolve_anchor` skips `panorama` both as anchor and target). Jobs use `scene_panorama` (`zaolang-generation-jobs` › `reference-asset-pipeline.md`), and pending graph jobs carry `mode="panorama"`.

## Recipes

1. **Catalogue entry**: add a `CatalogSkill` (unique `key`+`title`; image rows use `_IMAGE_OPERATIONS`) → `seed_covers/<key>.jpg` or `COVERS_PENDING` → `make seed` (prod: `zaolang-remote-deploy`).
2. **Category** (string column, no migration): enum in `back/app/models/enums.py` (+ `IMAGE_ASSET_SKILL_CATEGORIES`) → `make openapi` → every front copy (plaza `CATEGORIES_BY_CONTENT_TYPE`; `grep -rn 'CATEGORIES\b\|CATEGORY_LABEL_KEY' front/src`) → `skillLibrary.category*` copy.
3. **Character field**: `CharacterView` property → service create/update → `back/app/api/schemas/characters.py` → `make openapi` → `character-library.tsx`.
